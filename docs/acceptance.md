## 1. 证据记录格式

每条验收记录至少包含：

| 字段 | 说明 |
| --- | --- |
| 案例编号 | AC01—AC17 或子案例编号 |
| 构建版本 | 版本号与 Git 提交 |
| SHA-256 | 被测 EXE 的校验值 |
| 系统/浏览器 | Windows 版本、Android/iPhone 机型与浏览器版本 |
| 网络接入 | Wi-Fi/有线、是否 AP 隔离、防火墙策略 |
| 执行步骤 | 可复现的操作序列 |
| 期望 | 本文档的通过条件 |
| 实际结果 | 原始观察、截图/日志位置、测量值 |
| 结论 | 通过 / 失败 / 待验证 |
| 缺陷编号 | 失败时关联的问题编号 |

证据分层：

- `开发机`：自动化测试、构建检查、协议负例、本机双浏览器。
- `真机`：Android 与 iPhone 经 LAN HTTP 访问并完成收发。
- `现场`：目标教室电脑、实际 Wi-Fi、实际 U 盘路径、防火墙策略。

低风险文案与样式采用人工检查；状态竞争、权限、密钥路径、重置与有界队列必须有针对性验证。不得用开发机结果替代真机或现场结论。

## 4. 细分测试点

### 4.1 协议与状态（J01/J04/J05）

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| T-P01 | 未知 `v`、未知 `type`、未知字段 | 确定错误码；不修改状态 |
| T-P02 | 非法 Base64、错误 nonce 长度、非法 `seq` | `INVALID_MESSAGE`；不转发 |
| T-P03 | 非成员发送、非收件人确认、学生调用管理消息 | `NOT_MEMBER`/`FORBIDDEN`；无信息泄露 |
| T-P04 | 互邀、重复接受、超时后接受、旧定时器 | 只存在一个会话；旧事件无效 |
| T-P05 | 旧 `connection_epoch` 消息与关闭回调 | 被丢弃；不影响新连接 |
| T-P06 | 相同 `message_id` 同/不同载荷 | 同载荷返回原结果；改载荷 `ID_CONFLICT` |
| T-P07 | `round.reset` 同 `request_id` 同/不同载荷 | 幂等返回原结果；改载荷报错 |
| T-P08 | `round.reset` 与在途消息竞争 | 旧消息不进入新轮次 |
| T-P09 | 慢客户端队列溢出 | 仅关闭该连接；相关会话收到原因 |
| T-P10 | 公钥替换、篡改密文、上下文不符 | 会话关闭；不降级明文 |
| T-P11 | 加密消息夹带 `text`/`private_key` | `INVALID_MESSAGE`；无观察事件 |
| T-P12 | 4096 字节与 4097 字节正文（ASCII/中文/emoji） | 前者通过；后者拒绝 |

## 5. 负载与性能验收

- 场景：100 条学生连接，明文与加密会话混合，持续 5 分钟，每位学生约每 5 秒发送一条短消息。
- 接收端核对 `message_id`，不允许未报告的重复或丢失。
- 指标：发送到接收端确认的 p95 ≤ 500 ms（良好 LAN）；正常延迟、断线、限速和确认超时分开报告。
- 计时：同一发送端单调时钟，收到经 A 转交的接收确认后停止；不用不同机器时钟相减。
- 记录：进程内存、各队列和缓存峰值、失败数、淘汰次数。
- 结论边界：100 个模拟连接只说明服务端与协议表现，不证明课堂 Wi-Fi 能承载 100 台手机。
