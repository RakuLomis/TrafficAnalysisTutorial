# 局域网加密流量课堂工具需求规格

- 文档版本：1.0
- 冻结日期：2026-10-23
- 依据：`plan/traffic_classroom_implementation_plan.md` 1.0
- 状态：A01 契约文档，后续阶段以此为可追踪需求基线

## 1. 目的与范围

本工具用于课堂演示“加密流量分析能看到什么、不能看到什么”。教室电脑运行一个免安装的局域网转发服务 A，学生用手机浏览器加入，通过逻辑会话进行明文或端到端加密聊天；教师在本机页面点击会话边，查看 A 实际收到的应用消息内容与通信特征。

V1 只实现以下核心能力：

1. Windows 单 EXE 启动，内嵌前端资源，不依赖 Go、Node.js、Python、抓包驱动或外网。
2. 学生经 LAN HTTP 页面加入，使用临时昵称和安全随机 ID。
3. 全班共享公开拓扑，聊天正文只按会话参与关系分发。
4. 一对一逻辑会话，支持明文和 `nacl.box` 端到端加密两种模式。
5. 教师仅通过 `127.0.0.1` 受保护入口观察真实转发内容与统计。
6. 断线恢复、超时、拒绝、清空、满员等生命周期反馈。
7. 运行期聊天与密钥不持久化，进程重启无旧数据。

V1 明确不包含：文件传输、音视频、群聊、WebRTC 直连、真实网卡抓包、TLS 复现、账号密码、数据库、业务分类模型、历史导出、公网部署。固定长度填充等属于可选扩展 X01—X04，不阻塞 V1。

## 2. 角色与信任边界

| 角色 | 说明 | 权限边界 |
| --- | --- | --- |
| 学生 S | 手机浏览器页面，临时身份 | 只能看到公开拓扑、自己的会话、自己参与的正文/密文；不能取得管理权限或其他会话正文 |
| 教师 T | 本机 `127.0.0.1` 管理页面 | 可订阅观察记录、控制轮次、结束课堂；不能读取加密会话明文或私钥 |
| 转发服务 A | Go 进程内的 Hub 与 HTTP/WS 监听器 | 转发、校验、计数、保存有界观察记录；不执行服务端解密，不持久化聊天 |
| 被动观察者 | 课堂要讨论的假想网络观察者 | 只能看到真实链路可观察的元数据；本工具不主动抓包 |

加密模型限定为“端点浏览器程序可信，网络观察者不主动篡改网页或公钥”。安全随机数、公钥固定、nonce 规则只保证同一会话密钥下的正确使用；不承诺抵御恶意主机、恶意网页分发者或主动中间人。

## 3. 可追踪需求

验收编号引用 `docs/acceptance.md`。任务编号引用实施计划。

### R01 U 盘启动、服务端免安装

- 用户行为：教师双击 U 盘中的 EXE 即可启动；不需要安装任何运行时。
- 界面行为：控制台显示版本、学生入口地址、教师入口、当前网卡候选和错误提示；教师页面由程序自动打开。
- 数据边界：所有静态资源经 `go:embed` 内嵌；运行期不下载远程资源；聊天数据不写入 U 盘。
- 不满足即失败：要求安装 Go/Node/Python、依赖外部 `dist` 目录、启动时访问外网。
- 验收：AC13、AC14、AC16。任务：B03、B07、I01—I07。

### R02 手机浏览器访问 A

- 用户行为：学生扫描二维码或在手机浏览器输入教师展示的 LAN 地址。
- 界面行为：页面加载后建立到 A 的 WebSocket；地址必须是真实 LAN IPv4，不能显示 `0.0.0.0` 或 `localhost`。
- 数据边界：仅需 LAN，不需要公网；公共监听器默认 `0.0.0.0:8080`。
- 验收：AC01、AC13、AC17。任务：B04—B08、I03、I04。

### R03 临时昵称和不同圆点

- 用户行为：输入去除首尾空白后 1—16 个 Unicode 码点的昵称；允许重名。
- 界面行为：每个参与者获得唯一临时 ID、短编号和颜色；全班拓扑同步在线名单；重名用短编号区分。
- 数据边界：昵称按纯文本渲染；禁止控制字符；身份只在内存中存在。
- 验收：AC01。任务：C02、C06、C07、F02、F04。

### R04 学生选择对象与加密模式

- 用户行为：邀请方选择在线对象和“明文/加密”模式；对方看到模式后接受或拒绝。
- 界面行为：邀请卡片显示对象、模式、剩余时间；重复点击不会生成多个邀请；拒绝、取消和超时都有明确提示。
- 数据边界：模式在会话生命周期内固定，不可中途切换；每对参与者同一轮次最多一个未关闭会话。
- 验收：AC02、AC04。任务：D01、D02、D09、F03。

### R05 建立会话后出现无向边

- 用户行为：会话建立后双方看到连接彼此的边；消息活动可显示方向。
- 界面行为：边样式区分 `INVITED`、`NEGOTIATING`、`ACTIVE`、`CLOSED`；ACTIVE 边标注“明文”或“加密”；学生只能进入自己参与的会话。
- 数据边界：边表示逻辑会话，不表示网络链路或抓包路径；真实连接是每个学生到 A 的一条 WebSocket。
- 验收：AC02、AC03、AC04。任务：F04、F05、F09。

### R06 教师点击边查看通信

- 用户行为：教师点击拓扑中的会话边，选择观察该会话。
- 界面行为：明文会话显示 A 实际收到的真实正文；加密会话显示真实 Base64 密文、nonce 和允许的元数据；展示消息字节数、方向、时间、累计统计。
- 数据边界：观察记录来自 A 接受业务消息的位置；不来自客户端自报或网卡抓包；教师接口只在 loopback 监听并需 token 鉴权。
- 验收：AC03、AC04、AC06、AC12。任务：C05、G01—G08。

### R07 仅简单缓存，关闭清空

- 用户行为：教师可“新一轮”或“结束课堂”；学生可关闭会话或离开。
- 界面行为：重置后学生回到加入页；教师观察记录清空；结束时拒绝新加入，直到开始下一轮。
- 数据边界：服务端无聊天持久化、无数据库、无默认文件日志；客户端不写 localStorage/sessionStorage/IndexedDB；私钥与消息不主动持久化；进程重启无旧数据。
- 验收：AC09—AC11、AC15、AC16。任务：H03—H05、H07、H08。

### R08 面向被动观察的课堂演示

- 用户行为：教师对比明文与加密会话在 A 处可见的信息。
- 界面行为：明确标注“A 观察到的应用消息”，动画表示“A 接受了一条业务消息”，不是网络包或传播速度。
- 数据边界：加密在发送端浏览器完成，接收端浏览器解密；A 不接收加密会话明文、私钥或明文派生摘要；公共广播不含正文、密文、token 或密钥。
- 验收：AC03、AC04、AC05、AC12。任务：E01—E10、G03、G07、J03。

### R09 与加密流量分析结合

- 用户行为：教师观察同一会话的消息长度、方向、时间间隔、次数和方向切换。
- 界面行为：分别显示 `payload_bytes` 与 `ws_message_bytes`；时间轴标出单位与口径；标明历史窗口是否发生淘汰；累计统计不随淘汰回退。
- 数据边界：`payload_bytes` 明文为正文 UTF-8 字节数，加密为 Base64 解码后的密文本体字节数；`ws_message_bytes` 为 A 收到的完整 WebSocket 应用消息 UTF-8 字节数；两者都不是 IP/TCP 包长。
- 验收：AC06、AC07、AC15。任务：A05、G03—G08。

### R10 可在课堂连续操作

- 用户行为：断线、刷新、拒绝邀请、超时、清空、满员等场景均有明确反馈。
- 界面行为：聊天显示 `SENDING/ACCEPTED/CONFIRMED/UNCONFIRMED/FAILED`；断线禁发；恢复提示明确；慢客户端不阻塞其他会话。
- 数据边界：同页恢复只恢复身份，不恢复旧会话和旧密钥；刷新创建新身份；旧轮次和旧连接代次事件必须被丢弃。
- 验收：AC08—AC11、AC15、AC17。任务：C08、D03、D07—D10、H01—H07。

## 4. 关键交互规则

### 4.1 加入与身份

1. 学生首次加入提交昵称，A 返回 `welcome`，其中含 `participant_id`、短编号、颜色、`resume_token`、`connection_epoch`、`round_id` 和公开快照。
2. `resume_token` 只保存在当前页面内存中；60 秒内可恢复身份，恢复成功后轮换 token 和 connection epoch。
3. 页面刷新、恢复窗口超时或轮次改变时创建新身份。
4. 恢复成功后旧连接、旧邀请、旧会话、旧密钥和旧消息全部关闭，不自动重发。

### 4.2 邀请与会话

1. 邀请方选择对象和模式，A 校验在线状态、额度和“每对参与者唯一未关闭会话”。
2. 被邀请人接受：明文直接 `ACTIVE`；加密进入 `NEGOTIATING`，双方交换公钥并完成加密确认，双方 `ready` 后 `ACTIVE`。
3. 任一方可关闭会话；关闭后额度释放，同一对可重新邀请。
4. 邀请 30 秒超时，加密协商 15 秒超时；到期操作无效。

### 4.3 消息与确认

1. 只有 `ACTIVE` 会话可发送业务消息；发送前检查 UTF-8 4096 字节上限。
2. A 依据真实连接确定 `sender_id`，校验轮次、代次、成员关系、模式和长度，并生成唯一观察事件。
3. A 向发件人返回 `chat.accepted`（A 已接受，不代表收件人已处理）；向收件人转发 `chat.deliver`。
4. 收件人成功处理后返回 `chat.receipt`；A 生成 `chat.status`。5 秒无确认标 `UNCONFIRMED`，迟到确认可更新。
5. 首版不自动重发聊天；重复 `message_id` 同载荷返回原结果，不同载荷返回 `ID_CONFLICT`。

### 4.4 教师观察

1. 教师页面从本机 URL fragment 读取管理 token，读入内存后立即从地址栏移除。
2. 教师 WebSocket 首条消息认证 token，并校验 Origin 与请求 Host 属于本机教师入口。
3. 学生监听器不注册管理接口；学生不能通过参数或消息获得管理角色。
4. 观察记录只含 A 实际收到的内容与 A 的测量值；切换订阅不能串记录。

## 5. 非功能需求

### 5.1 容量

| 项目 | 目标 |
| --- | --- |
| 班级规划 | 50 名学生 |
| 学生连接验收目标 | 100 条 |
| 在线参与者上限 | 100 |
| 公共原始连接上限 | 120 |
| 在线与离线身份总上限 | 200 |
| 教师连接上限 | 4 |
| 每人会话额度 | 3（INVITED、NEGOTIATING、ACTIVE 合计） |

### 5.2 性能与时限

- 良好 LAN 下短文本从发送到接收端确认的 p95 目标 ≤ 500 ms。
- 邀请超时 30 s；加密协商超时 15 s；心跳 15 s；失联判定 45 s；身份恢复窗口 60 s；正常回执超时 5 s。
- 页面活动渲染合并间隔 ≤ 100 ms，但不改变原始事件时间或统计。
- 负载验收：100 条学生连接持续 5 分钟，明文/加密混合，每人约 5 秒一条。

### 5.3 安全与隐私

- 公钥 32 字节、nonce 24 字节；私钥和共享秘密只在浏览器内存。
- 管理 token 与恢复 token 使用 32 字节安全随机数的无填充 Base64url。
- 默认日志不含正文、私钥、恢复 token、管理 token。
- 页面中的昵称和正文按纯文本渲染，禁止 HTML 注入。
- 教师监听器固定 loopback，不提供对 LAN 开放的配置。

### 5.4 可访问性与兼容性

- 学生页在 360 px 宽度可操作，软键盘不遮住关键输入。
- 状态不只靠颜色表达，支持“减少动画”偏好。
- 首发声明仅覆盖实际验证过的 Windows 与手机浏览器版本；未实测环境不宣称支持。

## 7. 验收分层

- 开发机结果：自动化测试、协议负例、构建检查。
- 真机结果：Android/iPhone 在 LAN HTTP 来源完成加入、邀请和两种聊天。
- 现场结果：目标教室电脑、实际 Wi-Fi、实际 U 盘位置、防火墙与 AP 隔离策略。
- 没有执行的层级保持“待验证”，不得用开发机结果替代真机或现场结论。
